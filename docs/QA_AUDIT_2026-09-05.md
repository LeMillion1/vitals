# Real-environment QA audit — 2026-09-05

Status: in progress. This is evidence from the deployed application, not a claim
that every integration or every possible user journey has passed.

## Scope and safeguards

The audit exercises new member, doctor and trainer accounts in the real browser
against the deployed PostgreSQL application. Five clearly marked, synthetic
accounts were created: three members, one doctor and one trainer. No real health
record is used as a test fixture. The accounts and their synthetic records remain
for later removal at the user's request.

The first QA member temporarily received an audited platform-superadmin role to
exercise professional review. That extra role was revoked after review; the
account now has only the member role. Existing operator roles were not changed.
The two professional QA mailboxes were marked verified administratively only to
prepare invitation fixtures. This is **not** evidence of working mail delivery.

## Corrections validated locally, awaiting deployment acceptance

- A fresh record defaults to `Europe/Chisinau` even when the deployment uses
  another timezone, and Today replaces its subject-local clock with the browser's
  zone. The tested correction makes new records inherit deployment
  configuration, existing zones remain unchanged, and the rendered date/time
  remain one coherent snapshot with the page's facts and write form.
- Subject-specific cron jobs fire on the installation's schedule before the
  fan-out enters each subject's zone. Per-subject brief-time preferences are also
  not applied on shared installations. The scheduler correction has passed focused
  tests and independent review; no live scheduling pass is claimed yet.
- Scheduled Daily Brief generation loses its subject between phases on a shared
  installation. The correction preserves the explicit subject through initial
  preparation, recovery, dispatch, fallback, persistence and replay. Restricted
  PostgreSQL tests cover two subjects, every fresh-session binding, no platform
  scope, a single fallback artifact, and fake paid completion finalized even after
  the owner is suspended after dispatch. No real AI provider was called.
- Nutrition day-end checks and protein nudges can use historical Nutrition data
  while the module is disabled. The correction skips those paths for the disabled
  subject while preserving unrelated nudge categories; two-subject regressions pass.
- After a protected-export passphrase mismatch, correcting the confirmation leaves
  native custom validity set and prevents another submission. Live inspection
  confirmed the stale invalid state and no export request; the tested fix clears
  that state when either passphrase field is edited.
- An active numeric weight goal is hidden on Today when its baseline equals its
  target, despite being visible in Reports. The focused correction keeps the
  goal visible without inventing a percentage and excludes inactive goals.
- A full fast run exposed an intermittent empty shared-report checkpoint failure:
  its Python completion time could precede the database-generated start time.
  The focused correction uses the same database clock for all three initial
  timestamps; focused SQLite and PostgreSQL regressions and the final combined
  fast suite pass.
